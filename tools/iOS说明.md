# iOS 端说明

## 结论

**iOS 没有系统级悬浮窗。** 这是系统限制，不是功能没做。

Android 的 APK 悬浮窗在 iOS 上**没有对应物**，第三方 App 无法覆盖在另一个 App 之上。

---

## iOS 能用的三种方式

### 1. 添加到主屏幕（PWA，推荐日常用）

**操作**：Safari 打开站点 → 分享按钮 → 「添加到主屏幕」

**效果**：
- 从主屏幕图标打开，以独立窗口运行
- 没有浏览器地址栏，屏幕利用率更高
- 保留登录状态（localStorage 不丢）

**限制**：
- 切回游戏时 HUD **会被系统切到后台**
- 不会浮在游戏上

> 用 `file://` 或局域网 HTTP 打开时，「添加到主屏幕」可能可用，
> 但 manifest 的完整安装能力需要 HTTPS 托管。

### 2. iPad 分屏 / Slide Over

iPad 可以把 Safari 和游戏并排：

| 模式 | 操作 | 效果 |
|---|---|---|
| Split View | 拖分隔条 | 左右各占一半 |
| Slide Over | 从侧边滑出 | 悬浮小窗，游戏可能失焦 |

**优点**：真正同屏，能边看边点
**缺点**：占屏幕空间；Slide Over 下游戏可能暂停

### 3. 第二台设备

游戏在手机/平板，HUD 在另一台手机上开：

```text
calculator.html?hud=1&compact=1
```

**优点**：完全不挡游戏
**缺点**：目前**没有跨设备实时同步**，是独立记录，不是镜像

---

## 不推荐的方案

| 方案 | 为什么不行 |
|---|---|
| **画中画（PiP）** | 只能浮视频，不能点击、不能输入，做记录 HUD 没意义 |
| **越狱插件** | 能实现真悬浮，但需要越狱，不适合普通用户 |
| **录屏 / 直播叠加** | 只能看，不能操作 |
| **企业签名侧载** | iOS 依然不允许覆盖其他 App，做了也白做 |

---

## 网页端已做的 iOS 适配

技术上已经就绪的部分：

```text
apple-mobile-web-app-capable     → 全屏 PWA 模式
apple-mobile-web-app-title       → 主屏幕图标名称
apple-touch-icon (180/192/512)   → 图标
theme-color                      → 状态栏配色
manifest.webmanifest
  start_url = calculator.html?hud=1&compact=1
```

## 为什么不做 iOS 原生 App

| 障碍 | 说明 |
|---|---|
| **需要 macOS** | 编译 iOS 必须 macOS + Xcode |
| **需要开发者账号** | 真机调试需要签名（免费账号 7 天有效期） |
| **上架审核** | App Store 明确禁止覆盖其他 App 的行为 |
| **做了也没用** | 即使侧载成功，系统仍不允许悬浮覆盖 |

**结论**：这条路在 iOS 上走不通，不是投入不够。

## 实操建议

### 打 PVP 时

1. **iPad 用户** → 用 Split View，游戏左、HUD 右，体验最接近 Android
2. **iPhone 用户** → 用第二台设备（旧手机也行）开 HUD
3. **只有一台 iPhone** → 用全屏录入模式，打完切回来记

### 事后复盘

用 Safari 打开 `calculator.html`，屏幕大、看得全，比悬浮窗更适合分析。

## 常见问题

**添加到主屏幕后打不开？**
检查是否用 HTTPS 打开过。局域网 HTTP 下 manifest 可能不生效。

**分屏时游戏暂停怎么办？**
iOS 对后台 App 有限制。Split View 通常不会暂停，Slide Over 会。改用 Split View。

**能不能用快捷指令做浮层？**
不能。快捷指令只能触发动作，不能创建悬浮窗口。

**iPad 上键盘能用吗？**
可以。接蓝牙键盘后 Tab / 方向键都能操作表单。
